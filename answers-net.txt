Lab: Network driver —— 答案
==========================

本实验没有问答题，但为了作业完整性附上要点总结。

E1000 transmit (e1000.c: e1000_transmit)
----------------------------------------

1. 读 E1000_TDT 寄存器：硬件期望的下一个发送描述符下标。
2. 检查 tx_ring[idx].status 是否含 E1000_TXD_STAT_DD (Descriptor Done)。
   如果没有，说明硬件还没用完这一格——返回 -1（让上层释放 mbuf）。
3. 如果 tx_mbufs[idx] 不为空，说明这一格之前放过一个 mbuf，
   现在硬件已经发完，可以 mbuffree 回收。
4. 填 tx_ring[idx]：
     addr   = (uint64) m->head
     length = (uint16) m->len
     cmd    = E1000_TXD_CMD_EOP | E1000_TXD_CMD_RS
   EOP = "end of packet"，RS = "report status"。
5. tx_mbufs[idx] = m;  // 记录，等发完回收
6. regs[E1000_TDT] = (idx + 1) % TX_RING_SIZE;  // 推进 tail
7. acquire/release e1000_lock 保护。

E1000 receive (e1000.c: e1000_recv)
------------------------------------

1. idx = (regs[E1000_RDT] + 1) % RX_RING_SIZE;
   —— 驱动已经处理到的最后一格是 RDT，下一格是 RDT+1。
2. while (rx_ring[idx].status & E1000_RXD_STAT_DD) {
      m = rx_mbufs[idx];
      m->len = rx_ring[idx].length;   // 实际收到的字节数
      net_rx(m);                       // 交给协议栈
      rx_mbufs[idx] = mbufalloc(0);   // 分配新 buffer
      rx_ring[idx].addr = (uint64)rx_mbufs[idx]->head;
      rx_ring[idx].status = 0;        // 清零
      idx = (idx + 1) % RX_RING_SIZE;
   }
3. regs[E1000_RDT] = (idx - 1 + RX_RING_SIZE) % RX_RING_SIZE;
4. acquire/release e1000_lock 保护。

为什么需要锁
-----------

e1000_lock 保护：
  * 同一进程两次 e1000_transmit
  * 不同进程同时 e1000_transmit
  * transmit 和 receive 并发（transmit 由 net.c 在内核线程中调用，
    receive 由 e1000_intr() 在中断上下文调用）

不锁会出现 race：
  * 多个 transmit 同时写 tx_ring[idx] 和 regs[E1000_TDT]
  * transmit 和 receive 同时改 regs[] 寄存器

总结：e1000_lock 是一个粗粒度锁，把整个驱动的发送和接收串行化。
理论上可以用更细的锁（rx_ring 锁、tx_ring 锁分开），但本实验对
性能不做要求，一把总锁足够。
